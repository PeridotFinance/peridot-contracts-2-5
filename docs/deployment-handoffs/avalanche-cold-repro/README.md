# Cold single-run reproduction of the new suites (git 6c584f6d)

Each attempt ran in a **fresh, empty** isolated Foundry home (no RPC cache from any earlier attempt, run, proxy or agent; the home is deleted afterwards), against `https://api.avax.network/ext/bc/C/rpc` directly, no proxy. A home populated across retries is NOT used: `tools/run-avalanche-suite-cold.sh` creates a new home for every attempt (regression-tested in `tools/avalanche-repro-runner.test.sh`: three attempts, three distinct homes, all empty at start, all removed). A retry happens only for a positively identified transient RPC failure; anything else stops the run. Every attempt has its own directory with the full forge log (`suite.txt`, header = UTC time, git HEAD, command, empty-cache statement) and a `summary.tsv` line.

The four passing suites read little state at the pinned block and completed in seconds from an empty cache (the isolated home was verified to be populated during the run). The routes suite reads several DEX pools cold and exceeds what the public endpoint serves to this client: **nine attempts in total, none passed.** Attempts 1-6 at the standard pacing and attempts 7-9 (`routes-slow/`, client limit 2 compute units per second, backoff 5 s) each passed 26 of 38 and failed 12 tests with Cloudflare HTTP 429 (error code 1015); the slower pacing did not change the outcome. All failures were classified transient by `tools/avalanche-repro-classify.py`; because the same 12 fail every time, "transient" here means rate-limited, not intermittent. **What is established for the routes suite:** it passed 38/38 in the earlier warm-cache runs (development, and the agent's run `attempt09`, re-run by me), and 26 of its 38 tests pass from a cold cache; **what is not established:** a single cold run passing all 38 on this endpoint. A private archive RPC (as handoff 09 recommends) is the practical way to close this; I did not use one.

## Update 2026-11-05: private archive RPC (routes suite still outstanding)
- **Variable names.** The fork suites read `AVALANCHE_MAINNET_RPC_URL` (`vm.envOr`; empty means every test is SKIPPED, which is not a pass). The cold runner `tools/run-avalanche-suite-cold.sh` reads the same name and, if it is unset, falls back to `AVALANCHE_RPC` (the name the operator set in the shell). Neither value is written anywhere.
- **Masking (tested).** forge receives only the endpoint alias `avalanche_cold` (`--rpc-url avalanche_cold`, resolved from the environment variable `FOUNDRY_RPC_ENDPOINTS__avalanche_cold`), so the URL is in no argument list; the whole forge output passes through `tools/avalanche-redact-rpc.py` (forge's own errors contain the URL); the header says "private (URL and host masked)"; after each attempt the attempt directory is scanned for the URL, host and key-like tokens, and a hit makes the attempt exit 97. `tools/avalanche-repro-runner.test.sh` has 7 tests for this (alias, classification still works, no trace in any file, header and command line, a bypassing write is caught and only the file name is reported): 28 of 28 runner tests pass.
- **The cold routes run was NOT done.** The first call to the provider returned HTTP 403, "IP address ... is not on whitelist" (a source-address allowlist), on 2026-11-05 at about 15:50 and again at 16:21 UTC. Nothing was routed around it. Results stay as above: routes suite not reproduced from a cold run. It needs this machine's current address added to the provider's allowlist, or the run from an allowed host.
