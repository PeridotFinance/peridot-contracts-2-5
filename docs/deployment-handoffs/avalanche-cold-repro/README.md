# Cold single-run reproduction of the new suites (git 6c584f6d)

Each attempt ran in a **fresh, empty** isolated Foundry home (no RPC cache from any earlier attempt, run, proxy or agent; the home is deleted afterwards), against `https://api.avax.network/ext/bc/C/rpc` directly, no proxy. A home populated across retries is NOT used: `tools/run-avalanche-suite-cold.sh` creates a new home for every attempt (regression-tested in `tools/avalanche-repro-runner.test.sh`: three attempts, three distinct homes, all empty at start, all removed). A retry happens only for a positively identified transient RPC failure; anything else stops the run. Every attempt has its own directory with the full forge log (`suite.txt`, header = UTC time, git HEAD, command, empty-cache statement) and a `summary.tsv` line.

The routes suite reads several DEX pools cold and exceeds what the public endpoint serves to this client: **nine attempts in total, none passed.** Attempts 1-6 at the standard pacing and attempts 7-9 (`routes-slow/`, client limit 2 compute units per second, backoff 5 s) each passed 26 of 38 and failed 12 tests with Cloudflare HTTP 429 (error code 1015); the slower pacing did not change the outcome. All failures were classified transient by `tools/avalanche-repro-classify.py`; because the same 12 fail every time, "transient" here means rate-limited, not intermittent. **What is established for the routes suite:** it passed 38/38 in the earlier warm-cache runs (development, and the agent's run `attempt09`, re-run by me), and 26 of its 38 tests pass from a cold cache; **what is not established:** a single cold run passing all 38 on this endpoint. A private archive RPC (as handoff 09 recommends) is the practical way to close this; I did not use one.

## Update 2026-11-05: private archive RPC (routes suite still outstanding)
- **Variable names.** The fork suites read `AVALANCHE_MAINNET_RPC_URL` (`vm.envOr`; empty means every test is SKIPPED, which is not a pass). The cold runner `tools/run-avalanche-suite-cold.sh` reads the same name and, if it is unset, falls back to `AVALANCHE_RPC` (the name the operator set in the shell). Neither value is written anywhere.
- **Masking (tested).** forge receives only the endpoint alias `avalanche_cold` (`--rpc-url avalanche_cold`; see the 2026-11-05 correction below for how the alias is defined), so the URL is in no argument list; the whole forge output passes through `tools/avalanche-redact-rpc.py` (forge's own errors contain the URL); the header says "private (URL and host masked)"; after each attempt the attempt directory is scanned for the URL, host and key-like tokens, and a hit makes the attempt exit 97. `tools/avalanche-repro-runner.test.sh` has 7 tests for this (alias, classification still works, no trace in any file, header and command line, a bypassing write is caught and only the file name is reported): 28 of 28 runner tests pass.
- **The cold routes run was NOT done.** The first call to the provider returned HTTP 403, "IP address ... is not on whitelist" (a source-address allowlist), on 2026-11-05 at about 15:50 and again at 16:21 UTC. Nothing was routed around it. Results stay as above: routes suite not reproduced from a cold run. It needs this machine's current address added to the provider's allowlist, or the run from an allowed host.

## Update 2026-11-05 (later): routes suite reproduced cold on the private archive RPC
- **Result: PASS 38/38, one attempt, 364 s**, fresh empty home (0 RPC cache entries at start), git `c6d63a0b`, `FOUNDRY_PROFILE=debt_accounting`, client limit 10 compute units/s. Record: `routes-private/attempt1/suite.txt`, `routes-private/summary.tsv`. The post-attempt scan of that directory found no trace of the URL, host or key tokens. No rate-limit status was returned. The earlier HTTP 403 (source-address allowlist) no longer applied; the endpoint accepted the machine.
- **Runner defect found and fixed first (a runner bug, not a test result).** The first attempt (`routes-private-runner-defect/`, kept as a record) failed in 3 s with "could not instantiate forked environment ... No such file or directory ... avalanche_cold": forge 1.7.1 does **not** read endpoint aliases from `FOUNDRY_RPC_ENDPOINTS__<alias>`, so the alias was treated as a file path and the endpoint was never contacted. The 28 runner tests used a stand-in command and could not catch it. The runner now generates, per attempt and inside the fresh home, a copy of the **committed** `foundry.toml` plus one `[rpc_endpoints]` entry that is an environment reference (`avalanche_cold = "${AVALANCHE_MAINNET_RPC_URL}"`, expanded by forge at load); the generated file holds the reference, never the URL, and is deleted with the home. Verified that `src`, `libs`, `test`, `out` and `cache_path` resolve identically. The runner refuses (exit 2) if the committed config ever gains its own `[rpc_endpoints]`. The working-tree `foundry.toml` (uncommitted edits) is not used by the cold runner.
- **Not a full-suite cold reproduction of the whole gate**: the other four suites were cold-run at `6c584f6d`; this routes run is at `c6d63a0b`.
