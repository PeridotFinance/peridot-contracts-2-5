## 2. Fork tests: the treasury truth table through the monitor
`operator/test/fork/truth-table.fork.test.ts` drives the full `runCycle` path (event index, block-pinned multicall reads with accrual first, TWAP reference, rule, health, alerts) against a **local anvil fork at block 99,200,000** with the Foundry fixture: PW40, cap USD 5,000, three full-power borrowers, one half-power, one debt-free, 30 days of interest, AVAX -20% / -75%, liquidation to exhaustion, stale price, zero answer, treasury repayment. **All 17 rows of the table (treasury document 2.2) give the table's verdict exactly, and their amounts within 5 bp** (debt, debt value, collateral value, max recovery, shortfall). Further: the default is the only paid verdict and fires exactly once; the 1 h / 4 h / 24 h escalations fire on the chain's clock; a manipulated-low oracle with an honest reference reads `PRICE_DIVERGENCE` and pages the guardian; `observe()` reverting or pool liquidity below the floor reads `NO_REFERENCE_PRICE` (warn, then page after the persistence window); a reference at 10x, 0.1x, 1.2x, 0.8x of the oracle never creates a payment; rule mutants M1 and M3 change pinned verdicts; the incremental borrower index equals a full re-scan; the default alert resolves after the treasury repays. `real-pool.fork.test.ts` reads the REAL pool and the REAL Chainlink feed at the pin: TWAP USD 8.5651 against Chainlink USD 8.5491, gap 18.7 bp (tolerance 500 bp). Evidence: `avalanche-cash-only-operator-evidence/` (`fork-tests.txt` 17/17, `unit-tests.txt` 46/46, `source-mutations.txt`: 15 source mutants killed; one equivalent).

**Differences from the Foundry run, stated.** Accounts act by impersonation on a local fork (no key exists in the package); every transaction mines a block, so there are a few blocks of extra interest; the 30 days are applied by moving the market's accrual checkpoint back 2,592,000 blocks, which is what `vm.roll` does to the accrual; Chainlink feeds and the pool are MOCKS etched over the real addresses (as `vm.mockCall` does in Foundry), the mock pool's tick set to the same price, so the reference is quantised to 1 bp; the controller is the pilot's opt-in no-reward-token build; the deployment is replayed from the test fixture, not through `DeployAvalancheCashOnlyLending`. The unit suite pins the rule's own arithmetic (every verdict, the tolerance to the wei both ways, the exact recoverable boundary, dust, 28 wrong-reference pairs, conservative valuation).

## 4. Not done / limits
- **Executor, treasury Safe tooling, signer abstraction: not started** (steps 2-3 of the plan).
- Treasury health reads the USDC balance and the allowance; **pending Safe transactions are not read** (needs the Safe Transaction Service, an off-chain dependency).
- The "claims minus cash" alert of treasury document 5.3 is **not implemented**: as written it is positive whenever suppliers' claims exceed idle cash, which is normal with borrows outstanding; the intended condition needs a definition. Operator "last-action heartbeat" is limited to tracking each operator's nonce changes (no executor exists yet).
- The Telegram and webhook sinks are tested with a fake transport only; **never exercised against the real services**.
- Rate limits and reliability of the chosen RPC provider are untested in operation; the monitor is block-pinned and reports `monitor:blind` when the latest block is older than the limit or a cycle fails.
- **A USDC de-peg is not covered** (R_usdc := P_usdc); a simultaneous manipulation of Chainlink and the pool is not covered; the persistence hardening ("verdict must hold on two evaluations before paying") is not implemented (the monitor never pays; it only alerts).
- The 500 bp tolerance rests on a 14-day sample (treasury document 2.3.1).
- **Dependency note for the executor stage:** `npm audit` on `ethers@5.8.0` reports one advisory in `elliptic` (a risky ECDSA implementation, GHSA-848j-6mx2-7j84) with **no fix inside ethers v5**. The monitor never signs, so it does not use that code path; the key-holding process of steps 3-4 should either use an external signer only (hardware/KMS, as planned) with the local-signing code unused, or move to ethers v6 or viem. This is a decision for you before step 3.
- Not audited; off-chain code is outside the contract audit scope.

## Update 2026-11-06 (after review of this step)
The operator decided: `reference.minPoolLiquidity` = 50% of the trailing 7-day median, computed once at deployment by a documented script (built: `operator/scripts/compute-min-pool-liquidity.ts`); slippage bound 100 bp; signer type `foundry-keystore`; alert channel `log` until Telegram; the "claims minus cash" alert is defined as **unrecoverable debt** (built: `src/backing.ts`); the Safe-signing step is replaced by a **treasury keeper** (built: see `avalanche-cash-only-treasury-keeper.md`). Sections 3 and 4 above are superseded where they differ; the executor (step 3), operator setup steps (4) and Telegram (5) are not started.
